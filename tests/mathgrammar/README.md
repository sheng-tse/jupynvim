# Math grammar reference and golden cases

The Rust math grammar in `core/native/src/mathgrammar/` is a port of a JavaScript reference. This folder holds the reference, the helper that generates test cases from it, and the generated cases the Rust tests compare against. The module documentation of `core/native/src/mathgrammar/mod.rs` describes the grammar and its API; this file describes how the port is held to the reference.

## Files

- `mathgrammar.mjs`: the reference grammar (`extractMath`, `prepareTex`). The reference renders the markdown work is judged against were made with it. It is a verbatim copy and must not be edited.
- `katex_macros.mjs`: the reference's KaTeX `\newcommand` rule (`latexNewcommand`), taken verbatim from the reference renderer. It is no longer what the cases hold: it rewrote `\C` and `\Q` (which KaTeX does not predefine), missed the names KaTeX predefines that LaTeX lacks, took comments for definitions and passed `\providecommand` on (deviation D5, below). `gen_cases.mjs` runs it beside `katex_rule.mjs` and fails if the two differ on a document that holds none of the inputs D5 changes.
- `katex_rule.mjs`: the rule the Rust grammar applies (`katexNewcommand`, deviation D5), written the way KaTeX lexes its input and sharing nothing with the Rust code but the list of names. It is the oracle of the `katex` field.
- `katex_only.txt`: the list of names the rule knows, the control words KaTeX predefines that LaTeX with amsmath and amssymb does not define (246 for KaTeX 0.16.21). Generated by `gen_katex_only.mjs`; the Rust table `core/native/src/mathgrammar/katex_names.rs` is generated from it.
- `gen_katex_only.mjs`: writes `katex_only.txt` (`node gen_katex_only.mjs names <katex-package-dir>`, which needs KaTeX and a LaTeX with amsmath and amssymb), checks it (`check`: the names and the `# katex` and `# katex-names` header lines; another LaTeX banner prints a note, and where `latex` cannot run only KaTeX's version and number of predefined names are compared, with a note) and writes the Rust table (`rust`, stdin to stdout). It reads the macro, function and symbol tables of the KaTeX bundle, keeps the names real KaTeX refuses a `\newcommand` of, asks LaTeX which of them `\newcommand` accepts, and verifies the result with the real `\newcommand` in LaTeX. Regenerate it when the KaTeX version changes (0.16.47 adds `\overbracket` and `\underbracket`).
- `gen_cases.mjs`: generates case files (`battery`, `fixtures`, the long tags of `tags` and the random kinds `fuzz`, `ams`, `envs`, `d5` and `multline`) and the whitespace table from the files above (node, standard library only). The oracle of `prepared` and of the `mathjax` field is `mathgrammar.mjs` itself, loaded from its source with changes made to the text: for deviation D8 the two places that register a label under a tag (`if (tg) tag = tg[1];` with `for (const k2 of lab) labels[k2] = tag;` in the rows, `if (tg) labels[k2] = tg[1];` in an unnumbered display) take `tagText`, which `gen_cases.mjs` holds and appends to the module; for deviation D7 the row numbering of `prepareTex` (its line `rows = rows.map((row, ri) => {`) first sends a numbered `multline` to `multlineAsOneEquation`, held and appended the same way; for the `mathjax` field (deviation D6) the table of starred environments also has `eqnarray: 'eqnarray*', multline: 'multline*'` in place of the reference's `align*` and `gather*` and `flalign: 'flalign'` in place of `flalign*`, and the row loop tells `rowsAsSeen` when its environment is unstarred, so that a row left without a tag gets `\notag`; for deviation D9 (built on D8, with D7 inside it) `splitRows` hands over to `splitRowsAsSeen`, a numbered environment also needs `endSeen` of its body, the last row is dropped when `emptyAsSeen`, the whole row loop of `prepareTex` (from its line `rows = rows.map((row, ri) => {` to its `return row;`, D7's call site with it) becomes one call of `rowsAsSeen` or of `multlineAsOneEquation` with its `seenOnly` flag, the labels of an unnumbered display go to `displayAsSeen` and the leftover labels of every math to `removeSeenLabels` (all held in `gen_cases.mjs` and appended); for deviation D10 the join of the rows, `rows.join(' \\\\ ')`, loses its blank after the `\\`; for deviation D11 every take-out of the row loops (a label, a skip word, a tag `multlineAsOneEquation` moves, a label of an unnumbered display or left over) goes through `takeOut`, which leaves nothing in the modules of D7 to D10 and the blank of D11 in its own (one line, `function takeOut(st, s, at, end) { return ''; }`, replaced). Generation fails if a changed text is not found exactly once. Every document it writes is checked deviation by deviation: with D11 against D10 for a document where no take-out can meet a byte D11 reads (no `}` and no `\nonumber` or `\notag` right before a letter, `@`, `[` or `*`), with D10 against D9 (the D9 module with a mark after the blank of each join must give D9's text without the marks and D10's without the marks and the blank after each, so the join is all D10 changes), with D9 against D7 for a document that holds nothing D9 reads differently (a `%` in a math, or a backslash right before `\label{`, `\tag`, `\nonumber`, `\notag`, `\end{` or the `[` of a row break's argument), with D7 against D8 for one that holds no `multline` D7 reads differently (a `%` in it, a backslash right before a `\label`, `\tag`, `\nonumber` or `\notag`, or one of those before a `\\`), and with D8 against the unchanged reference for one that holds no tag D8 reads differently (a `{` or a backslash before the first `}` of its argument), as the `katex` field is checked against the reference's rule; a failed check of the oracle stops the generation, it never makes a random document be drawn again.
- `battery_additions.json`: 11 more `[name, source]` cases in the format of the battery (`tests/fixtures/markdown/math_battery_cases.json`), the settled edge cases that file does not hold: a digit on both sides of a pair of dollars, prices and decimals, a blank line inside `$$`, the doubled `\\(..\\)` and `\\[..\\]` forms, a `\newcommand` of a name KaTeX predefines, `multline`, and an escaped dollar in and out of math. It is kept out of the fixture copy, whose sha256 the fixtures README records, so the battery stays what it was. `golden/additions.cases` is generated from it.
- `golden/`: the generated files, committed so the Rust tests need neither node nor a JSON crate.

The copies must stay identical to what they were taken from:

```
mathgrammar.mjs sha256 7a8894599abb17f603e527602c5c380a7a7eb7599ce82358d44f8cae355a4090
katex_macros.mjs sha256 b1711e0b98bdb2772016e38a8eb2fabffa6e183439613263c697b0d3e8dd281e
```

## Running the checks

- `cd core && cargo test --release` runs everything that needs no node: the golden files (`core/native/tests/math_grammar.rs`, which reads them with `core/native/tests/support/casefile.rs`), the showcase rows (`core/native/tests/math_grammar_showcase.rs`: one comparison for each of 100 behaviors of the grammar, namely the 82 battery cases, 15 places where the renderers disagree and the grammar settles the reading, and three groups of settled and fixture cases, each printing `showcase <ID> ok` at the start of a line, so `cargo test --release --test math_grammar_showcase -- --nocapture | grep -c '^showcase .* ok$'` gives 100 with any number of test threads), the behavior tests for the ten deliberate differences below, the no-panic test over 50,000 random sources, the unit tests of the indexes, the examples in the module documentation, and the time budgets (`core/native/tests/math_grammar_perf.rs`).
- `bash tests/mathgrammar_spec.sh` needs node, and fails without it (the conformance proof needs the reference itself; it never skips). It checks the sha256 lines above (and the ones in `tests/fixtures/markdown/README.md`), regenerates every golden file from the reference and compares it with the committed bytes, and checks that `katex_names.rs` is what `gen_katex_only.mjs` makes of `katex_only.txt` (and, when `JNV_KATEX_DIR` names an unpacked `katex` package, that `katex_only.txt` is what KaTeX and LaTeX give today, with a note for another LaTeX banner and the KaTeX half alone where `latex` cannot run; `JNV_LATEX` names the latex binary), and compares five fresh random corpora with the Rust grammar field by field: general documents (`fuzz`), documents dense in numbering and references (`ams`), documents of repeated environment names (`envs`), displays dense in what the KaTeX rule reads (`d5`) and documents dense in numbered `multline` environments and tags with groups (`multline`). The run prints its seed and count; `JNV_MATH_SEED=<n>` and `JNV_MATH_COUNT=<n>` replay it (the count defaults to 20,000 documents of each kind), `JNV_MATHGRAMMAR_STALL_SECS=<n>` sets how long a comparison may go without finishing a document before it is declared stuck (default 120), and `JNV_MATHGRAMMAR_NODE_SECS=<n>` and `JNV_MATHGRAMMAR_CARGO_SECS=<n>` cap one node run (default 300) and the cargo test (default 1800).
- `bash tests/run_all.sh` runs both, in the sections `cargo test` and `math grammar spec`.

## Regenerating the golden files

Run from the repository root. The output is deterministic, so a second run gives byte-identical files.

```

node tests/mathgrammar/gen_cases.mjs battery tests/mathgrammar/battery_additions.json > tests/mathgrammar/golden/additions.cases
node tests/mathgrammar/gen_cases.mjs fixtures tests/fixtures/markdown > tests/mathgrammar/golden/fixtures.cases
node tests/mathgrammar/gen_cases.mjs fuzz 1 1500 > tests/mathgrammar/golden/fuzz.cases
node tests/mathgrammar/gen_cases.mjs ams 1 250 > tests/mathgrammar/golden/ams.cases
node tests/mathgrammar/gen_cases.mjs envs 1 400 > tests/mathgrammar/golden/envs.cases
node tests/mathgrammar/gen_cases.mjs d5 1 300 > tests/mathgrammar/golden/d5.cases
node tests/mathgrammar/gen_cases.mjs multline 1 300 > tests/mathgrammar/golden/multline.cases
node tests/mathgrammar/gen_cases.mjs tags > tests/mathgrammar/golden/tags.cases
node tests/mathgrammar/gen_cases.mjs whitespace > tests/mathgrammar/golden/js_whitespace.txt
```

- `battery.cases`: 82 documents, one per case of `math_battery_cases.json`, named after the case.
- `additions.cases`: 11 documents, one per case of `battery_additions.json`, named after the case. `core/native/tests/math_grammar.rs` compares them like the battery (`conformance_*_additions`) and `core/native/tests/math_grammar_showcase.rs` runs one comparison per showcase row on them and on the battery and the fixtures.
- `fixtures.cases`: 39 documents. The three markdown files as a whole (`md-fixture.md`, `hero.md`, `gauss.md`); then, for each of the three notebooks, one document per markdown cell (named `<notebook>#<cell index>`) and one document named `<notebook>` holding all its markdown cells in order.
- `fuzz.cases`: 1,500 random documents (seed 1, named `fuzz-1-<n>`), 10 percent of them with two or three sources. A draw that makes the reference throw is drawn again; the count of redraws is printed to stderr as `redrawn <n>`.
- `ams.cases`: 250 random documents (seed 1, named `ams-1-<n>`) made of numbered environments with repeated, forward and dangling labels and references, `\tag`, `\nonumber` and `\notag` in every position (and their near misses), unnumbered displays with labels, mismatched `\end` names, up to three sources each, and what the engines do not see or read with the row break (deviations D9 and D10): `%` comments that hold labels, tags, skip words, braces, row breaks and environments (to the end of their line or of the row), rows commented out on a line of their own, escaped commands (`{u\\label{a}}`), an escaped `%`, row breaks with a spacing argument or a star or a bracket on the next line or the row's text right after them, last rows that are a comment or only a break's argument, ends hidden by a comment or a backslash, and leftover labels the engines do not see, and take-outs that could join what they stand between (deviation D11: a label or skip word between a control word and a letter or `@`, at the start of a row or after a `\\` in a group before a `[` or `*`, and the near misses: letters after an escaped backslash, a digit or a blank after the command). They reach the order in which the grammar works on a row and the registration of labels, which the general documents hardly do. 150 of them come out differently from the reference.
- `envs.cases`: 400 random documents (seed 1, named `envs-1-<n>`) of bare `\begin{..}` and `\end{..}` that repeat names: nested equal names, an unclosed begin before a closed one, stray ends, starred names, quote prefixes. They reach the depth count of a name.
- `d5.cases`: 300 random documents (seed 1, named `d5-1-<n>`) of one to four sources, each of one to three `$$` displays of up to 16 pieces dense in what the KaTeX `\newcommand` rule reads (deviation D5): definitions and names (braced or not, one token or not, listed or not), comments, every line terminator, `\verb` in every form (a line terminator as the delimiter included), the addresses of `\url`, `\href` and `\includegraphics` and its brackets (a `}` where the address starts included, in a definition body and outside any group), escaped braces, white space other than a blank, multibyte and combining characters. The general documents hold these too sparsely to meet their mixes (a `\verb` whose delimiter is a line feed before a definition).
- `multline.cases`: 300 random documents (seed 1, named `multline-1-<n>`) of one to three sources, each of one to four parts: numbered `multline` environments (and a few `multline*`, `equation`, `align` and `gather` among them) of one to five rows, `\label`, `\tag` (starred, empty, with groups in it, unclosed after a stray `}`, a tag inside a tag), `\nonumber` and `\notag` and their near misses in any row, the same in a `%` comment (to the end of its line or of the row) and after an escaping backslash, an escaped `%`, a backslash before a character of two to four UTF-8 bytes, references in the rows and in text, forward and from other sources (deviation D7), and unnumbered displays with the same tags and labels (deviation D8), and tags, labels and skip words taken out from between a control word and a letter or from the start of a row before a `[` or `*` (deviation D11), the rows joined with a blank, a line feed or nothing after each `\\`. 242 of them come out differently from the reference. The other kinds hold a `multline` too rarely to meet these mixes, and none of them a comment or an escaped command in one.
- `tags.cases`: 34 documents of an explicit tag of 1 to 5,000 bytes (a display, a `\tag*`, a row of an `align`) referenced one to three times from the same cell or from other cells, forward references included, named `tags-<kind>-<length>[-<references>]`. They pin deviation D3 from below: the Rust grammar copies a tag into the references that fit its budget, and every document here is far inside it, so the output is the reference's, tags of 65 and 1,000 bytes included.
- `js_whitespace.txt`: the 25 code points JavaScript's `\s` matches, lowercase hex of at least four digits, one per line. Generation fails if `String.prototype.trim` ever disagrees with `\s`.

Two more modes help when writing a test by hand: `gen_cases.mjs json < source.md` prints the reference's output for one source, and `gen_cases.mjs json --doc < sources.json` does the same for a document given as a JSON array of sources (the output is `{texts, maths, prepared, katex, mathjax}`, `mathjax` given for every math).

## Case file format

UTF-8 text. Every length is a decimal byte count and every payload is followed by one `\n`, so a payload may hold any text, including lines that look like keywords.

```
JNVMATH 2
doc <name>                          (the name has no line break)
src <len>                           one per source, at least one, all before the text lines
<payload>
text <len>                          one per source, same order: the reference's extracted text
<payload>
math <source> <display 0|1> <block 0|1> <kind>      zero or more, in document order
tex <len>
<payload>
raw <len>
<payload>
prepared <len>
<payload>
katex <len>
<payload>
mathjax <len>                       only where it differs from prepared
<payload>
end
...more documents...
count <number of documents>
```

A document is a list of sources typeset in order, the way a notebook's markdown cells are: `prepared` is `prepareTex` (with deviations D7 to D11) over the maths of all sources, `katex` is `katexNewcommand` (`katex_rule.mjs`, deviation D5) of each prepared text with one set of defined names per document, and `mathjax` is the MathJax text, `prepareTex` with MathJax's starred forms of a numbered `eqnarray` and `multline` and its unstarred `flalign`, with `\notag` on a row of it left without a tag (deviation D6). The `mathjax` field is written only where it differs from `prepared` (a numbered `eqnarray`, `multline` or `flalign`, 375 maths of the committed files), and the reader takes `prepared` where it is absent; a `mathjax` field equal to `prepared` is not the format. `source` is the index of the source the math came from. Version 1 of the format had no `mathjax` field.

`core/native/tests/support/casefile.rs` reads this format. `tests/mathgrammar_spec.sh` regenerates every file here and compares it with the committed copy (proving the files are the reference's output), compares the copies above with their sha256 lines, and runs five fresh random corpora on every run of the suite.

## Where the Rust port differs on purpose

The port is identical to the reference on every input except eleven. Three are crashes, garbage or an engine error in the reference, one a wrong layout or an error in MathJax, one a wrong numbering of `multline`, one broken reference text, one a wrong numbering wherever a `%` comment or an escaped command stands in a numbered environment, one a row break's argument drawn as text and one a command taken out that joins what it stood between; two bound the memory and the time, and change the output only on inputs that name which they are (below), none of which a document holds unless it is made to:

1. D1: a `\begin{name}` whose name makes the reference build an invalid regular expression (a `**` anywhere after the name's first `*`) throws in the reference and fails the whole render. In Rust it is plain text.
2. D2: environment names and label keys are looked up in plain maps. The reference reads inherited object properties, so a display environment named `constructor` becomes the text of a function, `\eqref{constructor}` prints one, and a label named `__proto__` is silently dropped.
3. D3: the tag text that `\ref` and `\eqref` copy is limited per call of `prepare_tex`, that is per document, not per tag: a reference prints its tag while the bytes copied so far plus this tag stay within `REF_BUDGET_FACTOR` (4) times the TeX of all the maths plus `REF_BUDGET_BASE` (64 KiB), both in `core/native/src/mathgrammar/ams.rs`, and prints `??` (as for an unknown label) past it. The reference copies the whole tag into every reference, so `$$x \tag{<T bytes>}\label{a}$$` followed by `R` inline `$\ref{a}$` makes `R * T` bytes of output, quadratic in the source: 10 MB from a 20 KB source, 160 MB from 80 KB, about 28 GB from a 1 MB cell, inside the editor's process. A tag of any length referenced a few times (65 or 1,000 bytes, `tags.cases`) is copied exactly as the reference does; the budget only reaches a document whose references together copy more than 64 KiB of tag text and more than four times the TeX of its maths (a tag of kilobytes referenced dozens of times). The tag always stays in its display.
4. D4: the names of `\begin{name}` that hold a starred atom (two or more `*`: `a**`, `x*a*b*`; not a LaTeX environment) are matched within a work budget per text segment, `STAR_WORK_FACTOR` (16) units per byte of the segment plus `STAR_WORK_BASE` (1 Mi), both in `core/native/src/mathgrammar/index.rs`. A name of that kind that comes after the budget is spent and was not answered before is plain text, as in D1; the names answered before keep their answers, and the next text segment (after a code block, say) has a budget of its own. The reference builds a regular expression per name that backtracks without bound on a near miss, and the exact match of many such names against many others is quadratic (several seconds for 1 MiB). The budget is also spent when the merged groups kept for the names that match several others pass twice the occurrences of the segment plus 4,096, which bounds that memory without dropping any answer. Only a name with two or more `*` reaches either bound (no LaTeX environment is named so), and the second is nearer than the first: one plain environment name used a thousand times and eleven names with two stars that each match it (37.5 KB) reach it at the fifth, and every new such name after that is plain text, where the reference makes all of them environments (`deviation_d4`). Without the budget two shapes are out of reach: a name with `N` starred atoms read along a key of `M` bytes takes `M * N / 64` word steps (134 million for 256 KiB of text, four times as many for twice the text), and `K` distinct names that each match `K` keys cost `K * K`. 4 MiB of distinct `abc**` or `**abc` names spends about half of the budget.
5. D5: the KaTeX `\newcommand` rule (`katex_rule.mjs` here, `katex_newcommand` in `core/native/src/mathgrammar/macros.rs`). The reference's rule is a regular expression over the raw TeX with a list of ten names. KaTeX predefines neither `\C` nor `\Q`, so `$\newcommand{\Q}{\mathbb{Q}}$` became `\renewcommand{\Q}`, which KaTeX refuses ("when command `\Q` does not yet exist"), and every `\Q` after it was undefined. It lacked the names KaTeX predefines that LaTeX does not (`\argmax`, `\bm`, `\set`, `\ket`, `\coloneqq`, ...), so a preamble that defines one fails as a whole in KaTeX. It took the text of a comment (`% \newcommand{\R}{1}`) or of `\\newcommand` (a line break and letters) for a definition, so the real one after it was refused, and it passed `\providecommand` on, which KaTeX skips for a name it predefines (`\providecommand{\R}{\mathbf{R}}` drew KaTeX's own `\R`). Here the list is `katex_only.txt` (the 246 control words KaTeX 0.16.21 predefines that LaTeX with amsmath and amssymb does not define; 8 of them are among the reference's ten), the text is lexed as KaTeX lexes it (only a control word outside a comment and outside `\verb` text counts, and the text of a `\verb` whose delimiter is a line terminator runs to the next line terminator when that is the same one, `\verb<LF>abc<LF>` being the text `abc`; blanks, that is space, tab, line feed and carriage return, and comments may stand between the parts of the definition, where the reference's `\s` also skipped a no-break space and the other white space of JavaScript, which KaTeX takes for the name), and the first `\providecommand` of a listed name is passed on like the first `\newcommand` (`katex_rule_d5` and `macro_env_rule_state` pin it). Three more things are read as KaTeX reads them. The address of `\url`, `\href` and `\includegraphics` is read with `%` an ordinary character: a `%` there starts no comment (`\url{a%20b} \newcommand{\R}{1}` defines `\R`), the group runs to its matching brace (a backslash takes the next character, a `\verb` token is one token) and a definition inside it is not looked at; a group that is never closed ends the formula in KaTeX, so nothing after it is read, and so does a `}` where the argument starts with no group open around the command (`\url}`, `\includegraphics}`, `\includegraphics[x]}`, blanks before it allowed: KaTeX reports "Extra }"), while a `}` after a whole address (`\url{}}`) and a control symbol `\}` (the one token) are read on. `\includegraphics` first takes an optional argument in brackets, which KaTeX lexes as anywhere else (a `%` there starts a comment) up to the `]` outside any group; a `}` outside its groups is read like the `}` where the argument starts, and brackets never closed end the formula. With a group open around the command that `}` closes the group and the math is read on: the main scan keeps a count of open groups (a brace of a braced definition name included), because KaTeX parses no command in a definition body (`\newcommand{\img}{\includegraphics}`, `\def\lk{\url}`, `\newcommand{\fig}[1]{\includegraphics[width=#1]}`), in a braced name (`\renewcommand{\url}[1]{..}`), after `\let` (`{\let\lk\url}`) or in a macro's argument, and the definitions after them must be rewritten and claimed. The rule cannot tell those from a group KaTeX does parse and fails in (`{\url}`), so that math is read on too; it is an error in every engine, and only a later definition of a name the rest of it claims shows the difference. The rule follows a KaTeX error only in this scan, where KaTeX's reading of the argument fails and it reads nothing after it (an unclosed group and, with no group open, a `}` in the brackets or where the argument starts); everywhere else a math is read to its end, as LaTeX reads on after reporting an error, and the math shows as an error in every engine either way. KaTeX reads the `%` of an address as a character only where it lexes the address while it parses it. Inside text it has lexed before, the argument of another command (`\text{..}`, `\frac`, the second argument of `\href`) or a macro body, that `%` was read as a comment already, and the rule, which reads every address the first way, does not tell the two apart: in `$\text{\url{a%}\newcommand{\R}{1}<LF>}}$` followed by `$\newcommand{\R}{2}$` it takes `\R` from text KaTeX hides, and the second definition is left as `\newcommand`, which KaTeX refuses. That is a known gap: the exact rule needs the number of arguments of every command, the document's own macros included, and it takes a `%` in an address inside an argument, a KaTeX-only definition after it on the same line and another definition of that name later. A second known gap: the rule reads an address after one of these words wherever the word stands, unless the next token is a `}` that closes an open group, also where KaTeX takes the word as one token and reads no argument (the target of `\let`, a body without braces), so the token after it is lost: in `$\let\lk\url<LF>\newcommand{\R}{1}$`, and inside a group in `${\let\lk\url \newcommand{\R}{1} \R}$`, the `\newcommand` is taken for the address, `\R` is not rewritten and KaTeX refuses the math. It takes an alias of one of the three commands in that form with a definition of a KaTeX-only name as the very next token. A name in braces is exactly one token: only comments stand between the brace and the control word, and only blanks and comments between the word and the closing brace, so `\newcommand{ \R}{1}` and `\newcommand{\R x}{1}`, which KaTeX refuses, name nothing (the reference's expression took `R`). And a `\verb` token where the name should be is the name KaTeX is handed and claims nothing (`\newcommand\verb*!\newcommand\argmax!{x}` defines no `\argmax`). The generated corpora do reach D5 (the fuzz fragments hold `\Q`, `\argmax`, `\providecommand`, `%`, `\verb`), which is why the `katex` field comes from `katex_rule.mjs`; for a document with none of those inputs the reference's rule gives the same text, and the generator checks that for every document it writes.

6. D6: the MathJax text of a numbered `eqnarray`, `multline` and `flalign` (`NUMBERED` and `NOTAG` in `core/native/src/mathgrammar/ams.rs`). The reference writes the first two as `align*` and `gather*` for every engine: KaTeX's stand-ins, since KaTeX has neither environment. MathJax has both, and draws the stand-ins wrong for a `.md` file, where GitHub and LaTeX draw the environments themselves: `gather*` centers every row of a `multline` (whose first row starts at the left margin and whose last ends at the right), and `align*` pairs its columns right, left, with space between the pairs, so an `eqnarray`'s `a &=& b` shows a gap of about 1.7 em after the `=`. Under MathJax the grammar writes `multline*` and `eqnarray*` with the same rows, tags and references, which MathJax 3.2.2 draws with the layout of the numbered environments (`prepare_tex_for`, `prepare_document` with `Engine::MathJax`); `prepared` and the KaTeX text keep the reference's forms, which is what SPEC 4 settles for KaTeX. A numbered `flalign` is the one environment MathJax gets unstarred: MathJax 3.2.2 refuses a `\tag` in `flalign*` ("\tag not allowed in flalign* environment"), so the reference's `flalign*` with `\tag{n}` was an error box in a `.md` file (`$$\begin{flalign} && f(x) &= .. && \\ .. \label{eq:g} && \end{flalign}$$`, the whole derivation lost and every `\eqref` to it naming an equation not drawn), where GitHub draws the source; MathJax draws the unstarred `flalign` with the same explicit tags as LaTeX draws it. An unstarred environment numbers a row without a tag itself when MathJax's own numbering is on, so every row the numbering leaves without a tag (a `\nonumber` or `\notag` and no explicit tag) ends with `\notag` in that text, and MathJax draws the same rows and tags with its own numbering on or off. KaTeX has no `flalign` in either form; its text keeps `flalign*`. The references of the MathJax text keep a D3 budget of their own, so each text is what the reference's code gives with that engine's table.

7. D7: a numbered `multline` is one equation, as in amsmath (`number_multline` in `core/native/src/mathgrammar/ams.rs`). The reference numbers it row by row as if every row but the last had `\nonumber`: a `\label` before the last row is registered under no tag, so `$$\begin{multline}\label{eq:taylor} f(x) = .. \\ + ..\end{multline}$$` then `By $\eqref{eq:taylor}$` printed "By (??)" where LaTeX prints "By (1)" (forward references alike); a `\tag` there stayed in its row while the last row got a number too, so KaTeX drew two numbers and numbered every later equation one too high, and MathJax refused the `multline*` of D6 with "Multiple \tag" (a `\tag{$\ast$}` written at the top of a long equation showed its source in the error color); and a `\nonumber` or `\notag` there left the equation numbered. Here the first `\tag{..}` or `\tag*{..}` of any row is the equation's tag, a `\nonumber` or `\notag` in any row means no number, and otherwise the last row gets `\tag{n}`; every `\label` of every row is registered under that tag; and every tag of a row before the last is taken out of its row with its whole brace group and written at the end of the last row, where amsmath sets it, so KaTeX's `gather*` draws it there and two tags meet there and are an error in both engines, as in LaTeX. Only what the engines see counts: a `\label`, `\tag`, `\nonumber` or `\notag` in a `%` comment or after an escaping backslash (`{a\\tag{T}}` is a line break and the text `tag`) does not. A tag whose group does not close in its row (a row with a stray `}`, an error in every engine) stays where it is, and so does every tag after it in that row, so the text never loses a brace. `prepared`, the KaTeX and the MathJax text come from the same rows. A `multline` whose labels, tags and skip words all stand in its last row, outside comments and not after a backslash, comes out as it would without D7; MathJax 3.2.2 and KaTeX 0.16.21 draw one tag on the last row for each of these kinds.

8. D8: a reference prints its tag's whole brace group (`shown_tag` in `core/native/src/mathgrammar/ams.rs`). The reference copies what `\\tag\*?\{([^}]*)\}` captures, the tag's text up to its first `}`, so a label on a tag with a group in it or an escaped brace (`\tag{$x_{1}$}`, `\tag{I{a}}`, `\tag{a\}b}`) made every `\eqref` of it `\text{($x_{1)}`, an error in KaTeX and MathJax, in every numbered environment and in an unnumbered display; with D7 a label in any row of a `multline` refers to its tag, so it reached those too. Here the text is the tag's whole group, read with a backslash taking the next character (as rows are split), and a reference to a tag whose group does not close (only an unbalanced text has one, an error in every engine where it stands) prints `??`, which both engines draw. Whether a row has a tag and whether it is empty, which decide its number, are read as the reference reads them.

9. D9: the numbering reads the TeX as the engines see it (`Seen` in `core/native/src/mathgrammar/ams.rs`: a backslash takes the next character with it, a `%` hides the rest of its line), in every numbered environment, in a display that is none and in the labels left over. The reference reads the raw text, so a derivation with one step commented out the usual LaTeX way, `$$\begin{align} f(x) &= (x+1)^2 \\` LF `% &= x^2 + x + x + 1 \\` LF `&= x^2 + 2x + 1 \label{exp}\end{align}$$` then `By $\eqref{exp}$`, was split at the `\\` in the comment: the commented row was numbered and its `\tag{2}` written into the comment, so KaTeX and MathJax drew (1) (3), the reference printed "By (3)" and every later equation was one too high, where LaTeX, KaTeX numbering the `align` itself and MathJax's own AMS numbering give (1), (2) and "By (2)". It also read a `\label`, `\tag`, `\nonumber` or `\notag` in a comment (`E = mc^2 % \nonumber` lost its number, `% \tag{old}` replaced it, a commented label still resolved) or after an escaping backslash (`{u\\label{q}}`, a line break and text, became the unbalanced `{u\}`). Here rows are split only at a `\\` the engines see (nothing in a comment counts, braces included); a last row the engines see as empty is dropped as the reference drops a blank one (only white space and comments, after the argument `[..]` of the row break before it, as both engines drop it); a `\label`, `\tag`, `\tag*`, `\nonumber` or `\notag` counts, and is taken out, only where the engines see it, and one they do not see stays as it is, in the labels left over too; and an environment whose `\end` a comment on the body's last line hides (or a backslash escapes) is not numbered, since both engines report it as an error, and goes on as it is. Every row then ends before a `\\` the engines see or at the seen end of the body, so the `\tag{n}` written after it is always seen. A document with no `%` and no backslash before `\label{`, `\tag`, `\nonumber`, `\notag`, `\end{` or the `[` of a row break's argument comes out as it would without D9.

10. D10: each row follows its row break directly (`JOIN` in `core/native/src/mathgrammar/ams.rs`). The reference joins the rows with `' \\\\ '`, a blank after every `\\`, and neither engine looks past a blank for the argument of a row break (amsmath reads it only right after the `\\`), so the usual row spacing `$$\begin{align} a &= b \\[4pt]` LF `c &= d\end{align}$$` became `a &= b  \tag{1} \\ [4pt]` and KaTeX drew `a[4pt]c=b=d` and MathJax `a=b[4pt]c=d` (in `gather`, `alignat`, `eqnarray`, `multline` and with a negative length alike), and `\\*` became `\\ *`, a `*` MathJax draws. Here the row's own text follows the `\\`, so `\\[4pt]` and `\\*` stay the break's, and a bracket on the line after a `\\` stays the row's text, as in the source. Only blanks change for any other row, and the engines draw no blank in math, so the reference renders keep their pixels.

11. D11: a command taken out never joins what it stood between (`Glue` in `core/native/src/mathgrammar/ams.rs`). The reference takes a `\label`, `\nonumber` or `\notag` out of a row (and D7 a tag of a `multline` row before the last) leaving nothing in its place, so a control word before it and a letter after it became one word, `\alpha\label{x}b` the undefined `\alphab` (an error in both engines, where LaTeX draws alpha b) and `\nonumber\label{x}c` the word `\nonumberc`, which lost the row its skip; and a row break before it took a `[` or `*` after it for its argument, `a &= b \\\label{x}[c, d] &= e` the break `\\[c, d]` (a spacing that is no length: "Invalid size" in KaTeX, "Bracket argument to \\ must be a dimension" in MathJax, where the source draws `[c, d]`). Here a blank stands in the command's place exactly there: when the text copied since the last take-out (or since the start of the row, which may follow a row break) ends with a control word (letters, or `@`, which KaTeX reads as one, after an odd run of backslashes) and a letter or `@` follows, or ends with a row break (an even run of backslashes) and a `[` or `*` follows. Both engines end a control word at a blank and skip it, and neither reads a row break's argument after one. Every other take-out leaves nothing, as in the reference, and a break's own argument in the source (`\\[2pt]`, deviation D10) stays the break's.

The generated corpora never produce D2, D3 or D4 (their tags are short, their documents small), and the redraw removes D1, so the comparisons stay exact; D5 to D11 are part of the oracle, not of the comparison. Rust unit tests in `core/native/tests/math_grammar.rs`, `ams.rs`, `index.rs` and `macros.rs` pin the Rust behavior of all eleven.

## Per-cell numbering and the reference renders

`prepare_document` numbers equations across all sources of a document, as `prepareTex` does in this reference when it is given the maths of every cell. The reference renders of the notebook layouts (`vscode_nb_math-*.png`) were made one section at a time, so they show (1), (2), (3) where the whole fixture notebook numbers 3, 4, 5 for the same equations. A pixel test against those renders has to render the per-section sources. Numbering that restarts in every cell is `prepare_tex_for` (with the engine) per source followed by one `MacroScope` fold; which of the two a notebook view uses is that view's decision.

## Time

The reference is quadratic on a text with many unclosed delimiters (a 100 KB run of unclosed `\(` takes more than a second); the Rust grammar is linear. `core/native/tests/math_grammar_perf.rs` holds the budgets: the fixture and a 5,000-line document within a millisecond, seventeen adversarial inputs of 256 KiB within a few to a few tens of milliseconds each (twelve unclosed-delimiter shapes and five of multi-star environment names: distinct `abc**` and `**abc` names, a name with thousands of starred atoms read along a long key, thousands of names that each match thousands of keys, and thousands of names that each walk one long key), references to a long tag within a few milliseconds with the output at most the source times six plus 64 KiB, the MathJax text of 2,000 and 4,000 numbered `multline` and `eqnarray` displays with as many references (P4b, deviation D6: 1.2 ms for 4,000 maths, ratio 2.0; looking each math's own text up by a scan of all of them took 3.3 ms and 10.8 ms, ratio 3.26), one numbered `multline` of 256 KiB whose rows hold what D7 reads (tags, labels and skip words in comments and after a backslash, labels and tags with groups in them, every seen tag moved to the last row), in one row (P4c: 3.1 ms, 1.8 ms before deviation D9 kept in the rows what the engines do not see; reading the row from its start again for each command took 2.8 s) and in rows of four units (P4d: 3.1 ms; copying the moved tags for each new one took 5.4 and 17.0 ms for 256 and 512 KiB), one numbered `align` of 256 KiB whose rows hold what D9 reads (comments with braces, row breaks, tags, labels and skip words, rows commented out, escaped labels, each row after a break with its argument; P4e: 2.3 ms; reading the text from its start again for each label left over took 0.8 s), one numbered `flalign` of 256 KiB whose first row is one run of labels taken out from between letters, so the text written grows as one run of letters, and whose second row has the take-outs that leave the blank of D11 and the MathJax text's `\notag` (P4f, deviations D11 and D6: 2.1 ms; reading the end of all the text written so far for each take-out took 0.27 s and 1.06 s for 256 and 512 KiB), distinct multi-star names at 4 MiB within half a second (where the trie of hundreds of thousands of keys no longer fits in the caches), the KaTeX `\newcommand` rule on a line of 32,000 `\verb` that each have a delimiter of their own and find no closing one, which the rule reads once per line (P9: 2 ms for 256 KiB; a search to the end of the line for each took 1.6 s), the same rule on `\url{` and `\href{` groups that are never closed, which it reads once to the end of the text (P10: 0.2 ms for 256 KiB; going on from the word after each took 3.6 s), the same rule on `\verb` tokens whose delimiter is a line terminator, the kind that is a token (`\verb<LF>ab<LF>`) and the kind that is none because another line terminator comes first (`\verb<CR>cd<LF>`), each of which it finds the next line terminator of in time that does not grow with the rest of the text (P11: 0.3 ms for 256 KiB; copying the rest of the text for each took 2.7 s), on `\includegraphics` with brackets and addresses that close (P12a: 0.2 ms for 256 KiB; copying the rest of the text on entry took 0.46 s) and on brackets that are never closed, which it reads once to the end of the text (P12b: 0.2 ms for 256 KiB; going on from the word after each took 1.0 s), and the time for 512 KiB at most three times the time for 256 KiB, which a quadratic scan misses by far. The ratio is the check that does not depend on the machine. Every run, the calibration included, is timed with the CPU time of the calling thread (`CLOCK_THREAD_CPUTIME_ID`) and not the wall clock, because the grammar is single threaded and a wall clock also counts every moment the thread waits for a core: on a machine at a load average of 35 to 167 six of 28 wall-clock runs of the test failed on a grammar that is linear, and the same runs in CPU time did not. The two sizes of a ratio run alternately in rounds of five pairs; a round's ratio is its fastest large run over its fastest small run, and the lowest ratio of any round counts. The absolute budgets are for the machine they were measured on and are multiplied, never reduced, by how much slower the machine runs a fixed workload that has nothing to do with the grammar, timed the same way in the same test (it prints the factor). The multi-star shapes that a text can use to make the work grow faster than its size are bounded by the work budget of D4: 24 to 70 ns per byte of the segment as measured (cases A15 to A17: 7 to 18 ms for 256 KiB and 100 to 220 ms for 4 MiB; under load they can run at about twice that for a while, the slow mode the perf test describes), walk state of at most 16 bytes per byte of the segment (the sets, a handful in practice) plus a 16-byte frame per node of the path walked (at most the square root of twice the bytes of the names), and a peak memory of at most about 31 bytes per byte (4 MiB of distinct names: 130 MB, nearly all of it the index of the segment's names and occurrences; the trie is path-compressed, so it holds at most two nodes of about 50 bytes per distinct name whatever their length). The module documentation gives the numbers.
